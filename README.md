# 浅濑阅读器 Asase Reader

把 B 站专栏（opus）里的图片下载到本地，并当作离线漫画阅读器使用。
目标内容是「以专栏形式发布的分 part 连载漫画」：一个 opus = 一章。

> **仅用于个人离线阅读**。请遵守站点条款与版权，**不要二次分发下载到的内容**。
> 本仓库公开的是**代码**，不包含任何下载内容、书库数据或账号凭据：程序默认不使用
> 登录 Cookie，仅在解析到付费墙时由用户临时提供、且只存内存、退出即消失；
> 视频转图集功能需自备 ffmpeg，不随程序分发。
> 本项目按 MIT 许可开源（Copyright (c) 2026 浅濑凛 (Asase Rin)）。**未做代码签名**，
> 从网络下载的安装包会触发 Windows SmartScreen「未知发布者」，
> 请核对 Release 附带的 SHA256 后选择「更多信息 → 仍要运行」。

当前版本：**2.1.0**（见 [CHANGELOG.md](CHANGELOG.md)）

## 功能

- **下载**：粘贴链接（可混入整段文本，自动提取 ID）或导入 URL 列表文件，加入队列即自动开始；
  支持暂停 / 继续 / 取消、失败重试、每日请求上限。
- **导入**：把本地的一组图片或一个文件夹导入成一个章节，与下载章节共用同一套结构。
- **视频转图集**：把本地视频按场景变化抽成一组图片，**一个视频 = 一个章节**，
  与导入的图片一样先进入「未入库」再归入作品。调用的是**你自己的 ffmpeg**
  （PATH 里找不到就要在设置页填路径，不打包进 exe、不联网），原视频一个都不删。
  默认阈值 **0.02** 是 13 个样本实测出来的，见 CHANGELOG 的 1.15.2。不做去重 ——
  片源自带的重复图会原样保留，用下面的「删图片」自己删。
- **删章节里的图片**：章节行（书架的未入库区、编辑作品页的两类章节行）上的「编辑」
  进章节编辑页，点图片选中（按住 Shift 可选中一段），**点「删除选中的图片」并确认后才生效**，
  直接返回全部丢弃。删掉的文件直接从磁盘上删掉、不进回收站，剩下的图片重新编号成
  连续编号（阅读顺序不变）。至少留一张 —— 想清空整章请用「从书库移除」。
- **书架**：作品 → 章节两级；下载的章节和导入的图片都先进入「未入库」，再归类到作品。
  首页作品区只展示前 12 个，其余进「所有作品」页（每页 24 个 + 翻页 + 关键词搜索 +
  **标签 / 作者复选筛选**）。排序取 **max(最近更新, 最近阅读)**：刚下新章节的、
  刚读过的都靠前。作品卡片：左键整卡阅读，右键或悬浮 ⋯ 出菜单（编辑/导出/删除）。
- **标签**：只作用于作品层级。在编辑页新建 / 勾选 / 移除，标签池是全库 `tags` 的并集
  （派生，不单独存），筛选时可选「任一 / 全部」，作品页点标签可直接跳到筛选结果。
- **阅读**：单图模式（滚轮 / ←→ 翻页，单击图片 = 全屏开关）与连续竖向滚动两种模式，
  长图按宽铺满先滚完再翻页，图片懒加载，不记阅读进度。**单图模式可放大看细节**：
  Ctrl+滚轮（或触控板捏合）/ `+` `-` 缩放，`0` 复位；放大后可拖动平移，下限是「适应窗口」
  的原尺寸 —— 只有放没有缩。换页 / 切模式自动复位。
- **整理**：作品名 / 作者 / 章节名 / 章级注释自定义，上下排序、加章、自定义封面。

只抓图片：正文文字段与图片注释不解析、不存储。

## 运行

两种交付形态，任选其一：

| 形态 | 怎么用 | 装到哪 |
|---|---|---|
| 安装包 `AsaseReaderSetup-<ver>.exe` | 双击安装，简体中文向导、免管理员；开始菜单 / 桌面快捷方式 / 卸载项齐全 | 默认 `%LOCALAPPDATA%\Programs\AsaseReader`，向导可改路径 |
| 绿色版 `AsaseReader.exe` | 项目根目录双击即用，也可单独拷走 | 不安装 |

两种跑法的用户数据位置完全一样：书库由首启模态选，配置与界面偏好固定放在
`%LOCALAPPDATA%\AsaseReader\`；**不再把用户数据默认写在 exe 旁边**。
首次启动会先让你确认书库目录（已预填默认值）。

**不要同时开安装版和绿色版**：两者共用固定端口 28765 与
`%LOCALAPPDATA%\AsaseReader\webview_data`，会互相撞（本版不做单实例检测）。

开发模式：

```bash
pip install -e .
python -m asase_reader --gui          # 图形界面
python -m asase_reader <url> [url ...] # 命令行下载
python -m asase_reader --version
```

无 `pyproject` 安装时可临时用 `PYTHONPATH=src python -m asase_reader --gui`（或 `launch_gui.bat`）。

## 打包（2.1.0 起双轨）

一键出包（**发版只改 `src/asase_reader/__init__.py` 的 `__version__` 一行**）：

```bash
python tools/build_release.py --check   # 只体检：版本、工具链、计划，不写文件
python tools/build_release.py --build   # 自检 → 版本资源 → 两轨打包 → 安装包 → 校验值
```

`--build` 依次做：完整自检 → `tools/gen_version_info.py` 从 `__version__` 生成
`file_version_info.txt` 与 `installer/version.iss` → PyInstaller 分别出
`dist/onefile`（绿色单文件）与 `dist/onedir`（安装版目录，spec 由
`ASASE_PACKAGE_MODE=onedir` 切分支）→ Inno Setup 6 的 `ISCC.exe` 编译安装包
→ 写 `SHA256SUMS.txt` 与 `BUILD_INFO.txt` → **三件产物 mtime 都晚于 `src/**`
与 `gui.html`** 才算成功，否则直接失败。

产物都在 `dist/release/`（不入库）：

| 文件 | 说明 |
|---|---|
| `AsaseReaderSetup-<ver>.exe` | 安装包（onedir，正式交付） |
| `AsaseReader-<ver>-portable.exe` | 绿色单文件版；根目录 `AsaseReader.exe` 是同一件 |
| `SHA256SUMS.txt` | 上面三件的校验值 |
| `BUILD_INFO.txt` | git HEAD、版本、源码最新 mtime、三件 size/mtime/SHA256/`fresh` |

要点：

- 需要 **Inno Setup 6**（`ISCC.exe`）。脚本从卸载注册表读 `InstallLocation`，
  装到非系统盘也能找到；也可用环境变量 `ASASE_ISCC` 指定路径。**ISCC 缺位会明确
  失败，不会跳过安装包假装成功。**
- 官方 Inno 包不带简体中文，向导语言文件 `installer/ChineseSimplified.isl`
  **随项目入库**，`.iss` 走相对路径，不污染安装目录。
- 旧 onedir 产物会被挪到 `build/onedir_prev_<时间戳>` 而不是删，重复跑 `--build`
  是幂等的。
- **改了 `__version__` 必须重跑 `--build`**（`__init__.py` 属 `src/**`），否则
  产物文件名与 exe 里的版本仍是旧版。
- 只调试绿色版时可单跑 `pyinstaller AsaseReader.spec --noconfirm --clean`。
- 必须带 `pathex=['src']`（已在 spec 中），否则打出的 exe 报 `No module named asase_reader.cli`。
- `gui.html` 会被打进 exe：**改完前端必须重新打包**才生效。
- `console=False`，运行期异常不会弹黑框，前端有全局错误捕获与 `showError()` 兜底。

## 数据位置（2.0.0 起，安装版与绿色版相同）

| 跑法 / 路径 | 内容 | 会增长 | 是否入库 |
|---|---|---|---|
| `%LOCALAPPDATA%\AsaseReader\`（frozen：绿色版 / 安装版） | `config.json`、每日计数 `pages_*.json`、界面偏好副本 `ui_settings.json`、WebView2 数据 `webview_data\` | 否 | 否 |
| 仓库根 `.asase\`（源码运行） | 同上 | 否 | 否 |
| 「文档」`\AsaseReaderLibrary`（默认书库） | `chapters\<章节 id>\` + `library.json` + `_covers\` | 是 | 否 |
| 用户选定的书架 / 暂存 / 导出目录 | 大内容，可放在任意本地固定磁盘 | 是 | 否 |
| `.cache\` | 开发期临时脚本（**随时可删，别当作正式资产**） | — | 否 |
| `tests\` | 正式测试与夹具（含 v1 书架夹具、专栏页面 HTML 夹具） | — | **是** |
| `build\` `dist\` `AsaseReader.exe` | 打包产物 | — | 否 |

`PROJECT_ROOT` 只用于定位随包资源，不再作为数据默认锚点。书库、暂存、导出归用户；
配置、计数、WebView2 数据归程序，二者不混放。

安装版把程序本体装在 `%LOCALAPPDATA%\Programs\AsaseReader`（可改路径），与数据目录
`%LOCALAPPDATA%\AsaseReader` 是**两个独立目录**：覆盖安装与卸载只动程序目录，
不碰配置和书库；向导还会硬拒把程序装进数据目录，避免卸载时连数据一起清掉。

### 首次启动（不可跳过，但预填好了）

`setup_done` 为假时先弹书库目录模态：已有 `shelf_dir` 就预填它解析后的绝对路径
（源码模式升级后直接确认是幂等操作），全新配置预填「文档」下的 `AsaseReaderLibrary`。
模态没有取消，Esc / 点遮罩关不掉；右上角窗口关闭按钮仍可退出程序。确认成功才进入
书架、启动轮询并创建书库目录。

### 本机一次性迁移（没有自动迁移代码）

从 1.31.0 升到 2.0.0 时，**数据看起来会丢**，因为小数据换了位置：

1. 首启模态把书库选回旧位置（旧版默认是项目目录下的 `outputs`），
   或浏览选择新的本地固定磁盘目录；选回 exe 旁的 `outputs` 会出安装目录黄字，
   这是预期内、不阻断。
2. 界面风格 / 明暗 / 封面形状等偏好需要重设一次（副本搬到了新数据目录）；
   Cookie 本来只存内存，行为不变。
3. 每日计数文件也换了位置，切换当天配额会重置：**当天不要补量批量下载**。
4. 想换书库位置请自行复制 / 移动旧 `outputs`；程序不会自动搬迁。

### 目录配置（设置页）

- **书架目录**：唯一的用户可见目录，可填本地固定磁盘上的绝对路径（如
  `D:\Comics`）或浏览选择。留空保存回退到默认书库；**换目录 = 换书库**，旧库不迁移。
- **下载暂存目录**：留空即单目录模式；填了才启用「先落暂存、完成后搬进书架」。
  两个目录不能互为子目录；有任务正在下载时不允许切换目录。
- 不支持 UNC / 网络盘 / U 盘 / 光驱；拒绝盘符根、用户目录根、「文档」根与
  `%LOCALAPPDATA%\AsaseReader\` 及其子目录。安装目录及其子目录允许，但给黄色警告。
- 保存前先做静态校验，确认时才写可写探针；失败时内存配置、图片服务 root、
  `config.json` 与状态推送都不带新值。
- 空间：<100 MB 阻断保存，<2 GB 黄字警告；下载每章节 / 视频开始前 <50 MB
  标 `failed` + toast。双目录模式分别查书架盘与暂存盘。
- CLI `--state-dir` 默认走程序数据目录；`--out` 优先读配置里的书架目录，回退
  默认书库，绝不指向 DATA_DIR。`--dry-run` 豁免探针，保持零落盘。

### 实验性功能（设置页内，默认折叠）

- **下载暂存目录**：留空即单目录模式——下载直接落进 `chapters/<章节 id>/`，
  写完 meta.json 就算入库，下载中断留下的目录因为没有 meta.json 而不会被书架看到。
- **导入方式**：`移动到书架`（暂存目录腾空）或 `复制进书架`（暂存目录留备份，占双份空间）。

这两项收在「实验性功能」折叠区里，原因是**双目录模式的唯一真实用途是跨盘**，
而跨盘移动在本机（单盘）从未真实验证过；同盘时它更是零收益（同盘 move 就是一次
瞬间完成的 rename）。**已经启用过双目录的用户，该分区默认展开**，保证找得到入口。
出问题请先清空下载暂存目录、退回单目录模式。

### 章节模型（library.json v2）

- 章节是顶层 `chapters` 池，作品只保存 `chapter_id` 的有序列表；
  **未被任何作品引用的章节就是「未入库」**。
- `chapter_id`：B 站章节为 `opus_<opus_id>`（确定性），本地导入为 `c<随机 8 位>`。
- 章节目录名与作者 / 标题 / 所属作品无关，重新归类不会牵动磁盘路径。
- 两种来源写出同构的 meta.json；章节的标题 / 作者 / 来源写在自己的 meta.json 里，
  每个章节目录自洽。

### 导出（复制成普通文件夹）

入口：章节行的「更多 → 导出这一章…」/ 作品页的「导出作品…」/ 设置页的「导出整个书库」。

```
导出目录/作品名/
  work.json              作品名、作者、每章的标题·注释·opus_id·图片列表
  cover.jpg              作品封面
  第01话 章节名/
    00_cover.jpg         章节头图
    001.jpg  002.jpg …
```

- **导出的是副本**：书架里的原件保留，磁盘会多占一份空间。
- 图片**不转码、不重命名**（沿用 `001.jpg` 与 meta 里的顺序）；
  目标里已存在的同名文件**跳过不覆盖**。
- 章节文件夹名在对话框里选：`第01话 章节名` 或 `只用章节名`。
- 单章导出也带作品层，所以分批导出会合并进同一个作品文件夹（`work.json` 按序号累加）。
- 未入库的章节导出成顶层的「章节标题/」文件夹，不写 `work.json`。
- 导出目录不能放在书架目录里面（会被自检当成未完成的下载残留）。

## 自检与回归

### 一键自检（改完代码先跑这个）

```bash
python tests/selftest.py            # 全跑，约 1 分钟
python tests/selftest.py --skip-js  # 只跑 Python（没装 jsdom 时用）
python tests/selftest.py --serial   # JS 退回串行（排查 flaky 时用）
python tests/selftest.py --jobs=8   # 调 JS 并行度（默认 4）
```

JS 那 22 组默认并行跑（约 1 分钟全跑完，串行要 2 分钟）。
**并行只影响跑法，不影响判定**：每组退出码单独收集，有一个非 0 整体就非 0。

JS 那部分依赖 jsdom，只需装一次：

```bash
cd tests && npm install && cd ..
```

覆盖 48 组：数据层 / 迁移 / 导入 / 后端入库、**导出（目录结构 / 命名 / 跳过 / work.json）**、
**安装包双轨构建（spec 双模式 / 版本唯一来源 / `.iss` 静态契约 / 中文语言文件 /
一键出包链路 / 三件产物新鲜度）**、

其中四组是专门用来抓「只在运行时才炸」的问题的：

- `test_api_smoke.py`：反射遍历 `GuiApi` 的每个公开方法真实调用一遍。
- `test_download_offline.py`：用 `tests/fixtures/opus_*.html` 这份**真实页面夹具**
  跑完整的「解析 → 下载 → 落盘 → meta → 入库」链路，图片走打桩，**不发任何网络请求**。
- `test_ratelimit.py`：把风控红线钉死。这一项是变异测试补出来的 —— 之前把退避改成 0、
  让每日上限失效，全套自检**依然全绿**（详见下节）。
- `test_frontend_refs.py`：提取 `gui.html` 里所有函数定义与所有调用点（含 HTML 内联
  `onclick="..."`）做比对。同样是变异测试补出来的 —— JS 的函数引用运行时才解析，
  改了 `pickFolder` 的名字却漏改调用点，语法检查和 jsdom 结构测试**全都通过**，
  只有用户点那个按钮时才 `ReferenceError`（详见下节）。

### 这套自检有多灵？（变异测试实测）

把已知 bug 植回源码再跑自检，看它报不报错。结论：

| 植入的 bug | 自检是否发现 |
|---|---|
| 属性名写错 `outputs_root`（1.1.1 真 bug） | 发现 |
| 头图续传判断回退（1.1.2 真 bug） | 发现 |
| 锁改回不可重入导致导入死锁（1.1.1 真 bug） | 发现 |
| 路径穿越防护被移除 | 有专项断言 |
| 自然排序退化成字典序 | 有端到端断言 |
| **风控退避改成 0** | ~~漏~~ → 已由 `test_ratelimit.py` 补上 |
| **每日上限失效** | ~~漏~~ → 已由 `test_ratelimit.py` 补上 |
| **前端内部函数改名**（点了才炸） | ~~漏~~ → 已由 `test_frontend_refs.py` 补上 |
| 付费墙检测失效（恒判为无墙） | 发现（1.3.0 变异实测） |
| 预览版照常下载入库 | 发现 |
| 把 Cookie 写进 config.json（破不落盘红线） | 发现 |
| 保存后不清空输入框（明文留在页面上） | 发现 |

**所以它检不出所有问题。** 目前仍未被自动化覆盖的：阅读器的交互行为
（长图、连续滚动、翻页手感）、**观感类改动**（悬浮、阴影、间距、按下反馈、动画时长）、
真实网络下载、跨盘 move。
这几项只能靠下面的人工清单，以及发版时你自己点一遍。

> 为什么强调这个：1.1.0 就是只测了「我改过的那几个函数」，结果漏掉了
> 编辑页属性名写错、导入时死锁、头图重复下载三个运行时故障。
> **重构之后不要只测改动点，跑一遍 `selftest.py`。**

## 版本与发版

- 版本号唯一来源：`src/asase_reader/__init__.py` 的 `__version__`
  （`pyproject.toml` 用 `[tool.setuptools.dynamic]` 动态读取，不要两处都改）。
- 发版流程：

  ```bash
  # 1. 改 __version__，在 CHANGELOG.md 顶部加一节
  # 2. 重新打包并覆盖根目录 exe（如需分发）
  git add -A && git commit -m "chore(release): v1.0.2"
  git tag -a v1.0.2 -m "浅濑阅读器 v1.0.2"
  ```

- 提交信息用 Conventional Commits 前缀：`feat` / `fix` / `refactor` / `docs` / `chore` / `perf` / `test`。

## 风控红线（改动代码时不要触碰）

并发 1~2；页面随机 2~5s、图片随机 0.5~1.5s 延迟；每日总量上限；同一 URL 只下载一次；
遇 HTTP 412 指数退避且连续触发即停；不轮换 IP / 代理；不二次分发下载到的内容。

并发上限代码中只有一处定义（`backend.MAX_CONCURRENCY`），GUI 输入框的上限、
CLI 的夹取都从这里取值，`test_concurrency.py` 会校验三者与本节文案一致 —— 改它必须同步本行。

**登录 Cookie（1.3.0 起，仅充电专属内容需要）** —— 下面是它的全部约束，改代码时一条都不能破：

- **默认完全不用**：只有解析到付费墙（`module_paywall`）时才可能带上。
- **只存内存**：不写 config、不写日志、不落任何文件，退出程序即消失，下次要重新粘贴。
- **只用于抓取 opus 页面那一次请求**：图片下载走 CDN 裸请求，一律不带凭据。
- **不保存响应返回的新 Cookie**（避免顶掉浏览器里的登录态）。
- **拿到预览版一律报错并拒绝入库**，绝不静默存下残缺的一章。
- 判据只有 `module_paywall` —— 不要试图靠"图片是不是全黑"来猜，作者本来就可能在漫画里画黑页。
